The `legolization` module converts **task_graph-style legolization JSON** — the output format from the legolization paper and its accompanying tool — into BrickSim's `JsonTopology` format. This allows structures generated by external LEGO optimisation pipelines to be loaded directly into BrickSim environments without any manual schema translation. The module also ships a bundled `lego_library.json` containing brick dimension data for standard legolization brick types.

---

## Data types

### `LegoStructureBrick`

```python
from bricksim.topology.legolization import LegoStructureBrick
```

A `TypedDict` representing a single brick entry in a legolization task-graph JSON object. The outer JSON object maps string digit keys (`"1"`, `"2"`, …) to values of this type.

<ResponseField name="brick_id" type="int">
  Key into `lego_library.json` that identifies the brick type (determines footprint dimensions).
</ResponseField>

<ResponseField name="x" type="int">
  Grid X position of the brick's origin in stud units.
</ResponseField>

<ResponseField name="y" type="int">
  Grid Y position of the brick's origin in stud units.
</ResponseField>

<ResponseField name="z" type="int">
  Grid Z position of the brick in brick-layer units (not plate units).
</ResponseField>

<ResponseField name="ori" type="int">
  Footprint orientation. `0` = normal (height along X, width along Y); `1` = rotated 90° (height and width swapped).
</ResponseField>

---

### `DefaultLegoLibraryBrick`

```python
from bricksim.topology.legolization import DefaultLegoLibraryBrick
```

A `TypedDict` describing a brick type from the bundled `lego_library.json`. Extends `LegoLibraryBrick` (which only requires `height` and `width`) with optional fields used by StableLego.

<ResponseField name="height" type="int">
  Footprint height (along X) in stud units when `ori = 0`.
</ResponseField>

<ResponseField name="width" type="int">
  Footprint width (along Y) in stud units when `ori = 0`.
</ResponseField>

<ResponseField name="mass" type="float">
  Brick mass in grams (optional field, used by StableLego).
</ResponseField>

<ResponseField name="inventory" type="int">
  Inventory count for the brick type (optional field, used by StableLego).
</ResponseField>

## Functions

### `is_legolization_json`

```python
from bricksim.topology.legolization import is_legolization_json

def is_legolization_json(text: str) -> bool
```

A lightweight heuristic that checks whether `text` is a legolization task-graph JSON document. Useful for auto-detecting input format before calling a conversion function.

The function:
1. Attempts to parse `text` as JSON; returns `False` on any parse error.
2. Checks that the top-level value is a dict.
3. Finds the first key that is a string of digits and checks that the associated value contains all five required fields: `brick_id`, `x`, `y`, `z`, `ori`.

<ParamField name="text" type="str" required>
  Raw JSON string to inspect.
</ParamField>

**Returns** `bool` — `True` if the text appears to be legolization task-graph JSON; `False` otherwise.

<Note>
  This function does not validate field types or exhaustively check every entry — it only inspects the first digit-keyed entry it finds. Use it as a fast pre-filter before calling the full conversion.
</Note>

### `legolization_json_to_topology_json`

```python
from bricksim.topology.legolization import legolization_json_to_topology_json

def legolization_json_to_topology_json(
    lego_structure: LegoStructure,
    lego_library: LegoLibrary | None = None,
    color: ColorInput = (255, 255, 255),
    *,
    include_base_plate: bool = False,
    base_plate_size: tuple[int, int] | None = None,
    base_plate_color: InputColor | None = None,
) -> JsonTopology
```

Converts a parsed legolization task-graph structure into a `JsonTopology` dict compatible with the BrickSim native importer.

The conversion follows these rules:

- **Parts** — one `JsonPart` per brick in `lego_structure`, with `L` = footprint height (after applying `ori`), `W` = footprint width, and `H = 3` (one standard brick tall, matching the StableText2Brick convention).
- **Connections** — vertical adjacencies are inferred from the voxel grid: if a brick at layer `z` and a brick at layer `z+1` share any overlapping stud footprint positions, a connection is created. The lower brick provides studs (`stud_iface = 1`), the upper brick provides holes (`hole_iface = 0`).
- **Pose hints** — one per connected component; the lowest brick (or the base plate if present and connected) is used as the anchor, placed at `z = 0`.

<ParamField name="lego_structure" type="LegoStructure" required>
  Parsed legolization task-graph. A `Mapping[str, LegoStructureBrick]` whose keys are string digits (`"1"`, `"2"`, …). Typically obtained from `json.loads(text)`.
</ParamField>

<ParamField name="lego_library" type="LegoLibrary | None" default="None">
  Mapping from brick-id string to brick dimensions. If `None`, the bundled `lego_library.json` is loaded automatically via [`load_default_lego_library`](#load_default_lego_library).
</ParamField>

<ParamField name="color" type="ColorInput" default="(255, 255, 255)">
  Brick colour(s). Accepts:
  - A single `(r, g, b)` tuple — applied uniformly to all bricks.
  - A `list` of `(r, g, b)` tuples — applied per brick in sort order.
  - `None` — equivalent to white `(255, 255, 255)`.
</ParamField>

<ParamField name="include_base_plate" type="bool" default="False">
  If `True`, an additional base plate part is injected into the topology. The base plate is automatically connected to all bricks resting at the lowest grid layer (`z = 0`) and serves as the pose-hint anchor for the whole assembly.
</ParamField>

<ParamField name="base_plate_size" type="tuple[int, int] | None" default="None">
  `(width, height)` of the optional base plate in stud units. Ignored unless `include_base_plate=True`. If `None`, the size is inferred from the bounding box of the structure.
</ParamField>

<ParamField name="base_plate_color" type="InputColor | None" default="None">
  RGB colour `(r, g, b)` for the optional base plate. Ignored unless `include_base_plate=True`.
</ParamField>

**Returns** `JsonTopology` — a fully populated topology dictionary ready to be serialised with `json.dumps` or passed directly to the BrickSim importer.

---

### `load_default_lego_library`

```python
from bricksim.topology.legolization import load_default_lego_library

def load_default_lego_library() -> dict[str, DefaultLegoLibraryBrick]
```

Loads the bundled `lego_library.json` from the package data directory and caches it in a module-level variable. Subsequent calls return the cached dict without re-reading the file.

**Returns** `dict[str, DefaultLegoLibraryBrick]` — brick library keyed by legolization brick ID string (e.g. `"9"`, `"10"`).

**Raises** `FileNotFoundError` if the bundled `lego_library.json` cannot be found in the package directory.

## Usage example

```python
import json
from bricksim.topology.legolization import (
    is_legolization_json,
    legolization_json_to_topology_json,
)

with open("structure.json") as f:
    text = f.read()

if is_legolization_json(text):
    lego_structure = json.loads(text)
    topology = legolization_json_to_topology_json(
        lego_structure,
        color=(255, 165, 0),        # orange bricks
        include_base_plate=True,
        base_plate_size=(20, 20),
        base_plate_color=(100, 100, 100),
    )
    print(f"Converted {len(topology['parts'])} parts "
          f"and {len(topology['connections'])} connections")

    # Optionally sort connections into assembly order before use
    from bricksim.topology.ordering import bfs_sort_connections
    topology = bfs_sort_connections(topology)

    # Save for the native importer
    with open("structure_topology.json", "w") as f:
        json.dump(topology, f, indent=2)
```

<Tip>
  Combine `legolization_json_to_topology_json` with [`bfs_sort_connections`](/api/topology/ordering) to produce a topology whose connections are already in a valid sequential assembly order. This is required by the BrickSim environment's step-by-step assembly planning mode.
</Tip>

<Warning>
  The legolization format uses brick-layer units for `z` (one unit = one standard LEGO brick height). BrickSim's topology format uses plate units internally (`H = 3` per brick layer). The conversion handles this automatically — do not multiply `z` values before passing to `legolization_json_to_topology_json`.
</Warning>
